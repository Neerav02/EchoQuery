# Phase 10: Milestone 3 — Docker and Infrastructure Remediation

## Objective
Resolve the confirmed Docker API port mismatch and align container startup, healthcheck, Compose port mapping, and frontend API URL configuration across EchoQuery v2.0's deployment manifests.

## Execution Context
- **Planning only**: Do not modify Dockerfiles, Compose files, `.env`, or start/restart containers during planning.
- **Verified Codebase State**:
  - `app/Dockerfile:58`: `EXPOSE 8000`
  - `app/Dockerfile:62-63`: `HEALTHCHECK ... CMD curl -f http://localhost:8000/docs || exit 1`
  - `app/Dockerfile:66`: `CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "80"]` *(mismatch: binds port `80` instead of `8000`, breaking healthcheck and Compose `8000:8000`)*
  - `app/main.py:210-212`: Dedicated lightweight `GET /health` endpoint returns `{"status": "healthy", "service": "echoquery-api", "timestamp": time.time()}`.
  - `docker-compose.yml:10`: `ports: - "8000:8000"` (`api` service)
  - `docker-compose.yml:70`: `API_URL: http://api:8000` (`frontend` service)
  - `frontend/main.py:12`: `default_api = os.getenv("API_URL", "http://127.0.0.1:8000")`
  - `supervisord.conf:8`, `k8s/apps-hpa.yaml:21,34,40`, `Procfile:1`: All already standardize on port `8000` and `/health`.
- **Cross-milestone dependency**:
  - Depends cleanly on Phase `08` (`08-01`) regarding runtime `ENVIRONMENT` / `JWT_SECRET_KEY` expectations when containers boot in Compose.

## Task Order & Breakdown

### Task 10-01: Align API Container Port and Healthcheck (`app/Dockerfile`)
- **Order**: 1
- **Dependencies**: None (logically independent; coordinate runtime env check with Phase `08-01`)
- **Affected Files**:
  - `app/Dockerfile:58-66`
- **Implementation Plan**:
  - Update `app/Dockerfile:66` from `--port 80` to `--port 8000` (keeping `main:app` or verifying module path relative to `WORKDIR` in `app/Dockerfile` so `uvicorn` binds `0.0.0.0:8000`).
  - Update `app/Dockerfile:63` healthcheck target from `http://localhost:8000/docs` to `http://localhost:8000/health` (aligning with `app/main.py:210` and `k8s/apps-hpa.yaml:34,40`).
  - Verify `curl` is installed in the runtime stage of `app/Dockerfile` so `HEALTHCHECK` succeeds at container runtime without failing on missing binary.
- **Risks & Mitigations**:
  - *Risk*: Switching `/docs` to `/health` or changing `CMD` flags could fail if `curl` is absent in slim image or if `WORKDIR` differs between Compose and standalone builds.
    - *Mitigation*: Inspect `app/Dockerfile` lines 1-57 during execution to confirm `WORKDIR`, `PYTHONPATH`, and `curl` availability before finalizing the `Dockerfile` diff.
  - *Risk*: Unprivileged user vs port `< 1024`: previously binding `--port 80` as non-root would also fail without privileges; `--port 8000` resolves that cleanly.
- **Acceptance Criteria**:
  1. `app/Dockerfile` `EXPOSE`, `HEALTHCHECK`, and `CMD` all use port `8000`.
  2. `app/Dockerfile` `HEALTHCHECK` hits `http://localhost:8000/health` and uses an installed HTTP probe binary (`curl`).
  3. Static inspection / container config validation confirms API listens on `0.0.0.0:8000` matching `k8s/apps-hpa.yaml`, `supervisord.conf`, and `Procfile`.

### Task 10-02: Align Compose Mapping, Frontend API URL, and Runtime Env Contract (`docker-compose.yml`, `frontend/main.py`)
- **Order**: 2
- **Dependencies**: Task `10-01` and Phase `08` (`08-01` production JWT requirement)
- **Affected Files**:
  - `docker-compose.yml:6-72`
  - `frontend/main.py:12` (and WebSocket URL construction sites if applicable)
- **Implementation Plan**:
  - Audit `docker-compose.yml` (`api`, `worker`, `frontend`, healthchecks, `depends_on`, and `ports`) to verify:
    - `api` exposes `"8000:8000"` matching `app/Dockerfile:66`.
    - `frontend` receives `API_URL: http://api:8000` matching `frontend/main.py:12`.
    - If `docker-compose.yml` sets `ENVIRONMENT=production`, verify `JWT_SECRET_KEY` is passed through from `.env`/environment without hardcoding any secret value in `docker-compose.yml`. If Compose defaults to `development` or env pass-through (`JWT_SECRET_KEY: ${JWT_SECRET_KEY:-...}`? No — fail fast in prod or leave unset unless `.env` provides it), document the exact env variable contract clearly without modifying `.env`.
  - Audit `frontend/main.py` around `API_URL` and WebSocket client connections (coordinate with Phase `08-02` if the Streamlit UI opens `/ws/stream/{job_id}` so it sends the user's bearer token when authenticated).
- **Risks & Mitigations**:
  - *Risk*: Hardcoding a fallback `JWT_SECRET_KEY` in `docker-compose.yml` would re-introduce a default-secret vulnerability matching Phase `08-01`.
    - *Mitigation*: Never embed fallback production JWT secrets in `docker-compose.yml`; rely on explicit environment/secret injection when `ENVIRONMENT=production`.
  - *Risk*: `frontend` container fails to reach `api` on startup before FastAPI binds `:8000`.
    - *Mitigation*: Ensure `docker-compose.yml` `api` healthcheck + `frontend` `depends_on` condition (if modified) align on port `8000` `/health`.
- **Acceptance Criteria**:
  1. `docker compose config` validates cleanly with zero syntax/interpolation errors.
  2. `api` port mapping (`8000:8000`), `app/Dockerfile` (`--port 8000` + `/health`), `frontend` `API_URL` (`http://api:8000`), and `frontend/main.py` default (`http://127.0.0.1:8000`) all reference port `8000` consistently.
  3. Any `frontend/main.py` API/WebSocket references align with Phase `08-02` auth expectations and contain no port `80` leftovers.
